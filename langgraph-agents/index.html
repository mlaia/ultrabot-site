Why a graph, not a loop

A free-running loop is easy to demo.
A graph is easier to operate.

A free loop works in a demo. In production, the model picks what to say and which tool to call, but the graph decides what is allowed next. Fixed structure where the process is known, model judgement where it helps. More on what an Ultrabot agent does.

01

Typed shared state

Saved after each step, so a run can pause, resume or be replayed.

02

Tool calling with limits

Validated inputs, caps per turn, timeouts, and a defined reply when a tool fails.

03

Human-in-the-loop steps

Sending, booking or refunding waits for a person to approve, edit or reject.

04

Branches, retries & fallbacks

A failed search is retried; an unsure answer goes to a person, not the user.

05

Multi-agent only when it helps

Each extra agent adds delay and cost. We split only when tests show a gain.

06

Streaming to the interface

Users see progress as it happens, and a voice can start at the first sentence.

Before we start

Good questions. Straight answers.

When is LangGraph the right choice over a simple chain?

When the assistant has to take several actions in order, recover from failures, pause for a person or resume later. For a single retrieval-and-answer step, a simple chain or a direct API call is easier to maintain.

Can a LangGraph agent run on our own cloud?

Yes. The graph is ordinary Python, so it runs in a container or serverless function on AWS, Azure or Google Cloud, or on your own servers, with any model your policies allow, including models through Amazon Bedrock.

Which model should the agent use?

We test candidate models on your evaluation set and compare success rate, latency and cost. Often a smaller, faster model handles routing and simple steps while a stronger model handles the hard ones.

How do you stop an agent from taking a harmful action?

Tools only do what their code allows, inputs are validated, and consequential actions stop at an approval step. The agent cannot reach systems it was not given a tool for.

Can it work in Hebrew?

Yes. We have built assistants that work in Hebrew and English, including retrieval over mixed-language content. Hebrew needs its own test cases, because tokenisation, search and model behaviour differ from English.
